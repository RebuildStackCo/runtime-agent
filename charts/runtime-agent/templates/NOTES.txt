CHECK ONE THING: the NetworkPolicy needs a CNI that enforces it.

This release created a NetworkPolicy restricting the controller's node-report
receiver to the node DaemonSet. Kubernetes accepts that object on every cluster,
including clusters whose CNI ignores it — there is no error and no warning, so
an unenforced policy looks exactly like an enforced one.

Verify it rather than assume it. Calico, Cilium, Antrea and GKE Dataplane V2
enforce policies; EKS does so only with the VPC CNI's network-policy agent
enabled, and kind's default CNI does not enforce them at all.

  kubectl -n {{ .Release.Namespace }} get networkpolicy {{ include "runtime-agent.controllerName" . }}

What this changes if it is not enforced: the receiver on port 8080 is reachable
by any pod in the cluster. What it does not change: what a caller may say. Every
request is authenticated by audience, signature against your cluster's JWKS, a
pinned ServiceAccount subject, and the node named in the caller's own token, and
none of those depend on your CNI (ADR 0040).

The policy has a second rule, on port {{ include "runtime-agent.healthPort" . }}, with no source restriction: the
probes come from your kubelet at the node's address, which no pod selector can
name. What it admits is two read-only paths that answer about the agent and name
nothing in your cluster (ADR 0069).
